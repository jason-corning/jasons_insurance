Security boundary

Credentials stay out of chat and context variables

Passwords, reset tokens, one-time codes, payment data, access tokens, and session cookies were not created as context variables. The Help Center requires OAuth 2.0 Authorization Code Flow for authenticated widget conversations. The current insurance site exposes cookie-based login but not OAuth authorization/token endpoints, so authenticated mutations remain routed to the secure site until a real OAuth client is available.

D-10High

OAuth instructions say Classic workflow, but Autoflows expose OAuth Sign In

Tenant

The Actions drawer inside the “Cancel coverage” Autoflow includes “OAuth Sign In — Sign in the end user for the duration of the conversation using OAuth.” Action Builder also exposes an Authentication Client form requiring Name, Client ID, Client Secret, Auth URL, Token URL, authentication type, and optional scope.
